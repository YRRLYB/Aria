# 0.3.13-beta.0 验证记录

环境：Windows 11（10.0.26200），Electron 43.0.0，内置 mpv 0.41.0，x64。

## 自动化检查

```powershell
npm.cmd test
npx.cmd tsc -b --pretty false
npm.cmd run dist:beta
node scripts/test-desktop.cjs --resources release/win-unpacked/resources
```

33 项单元测试通过，覆盖原有队列、快捷键、歌词、缓存等功能，以及本次增加的封面尺寸、解码失败恢复、播放状态过滤、mpv 停止与替换加载竞争、过期暂停回执、无缝续播与手动加载区分。

桌面集成测试使用独立用户目录、随机端口和独立 Windows App ID，不修改已有曲库与播放器设置。它使用已打包的 `app.asar`、原生模块、mpv 和后端依赖，由相同版本的 Electron 启动。使用 Windows `GlobalSystemMediaTransportControlsSessionManager` 读取实际系统会话并发送控制命令，而非模拟 JavaScript 媒体按键。

- 浏览器、共享、独占、再返回浏览器：校验实际输出状态，以及闲置 mpv 的释放。
- 系统卡片：歌名、歌手、专辑、封面、上一首、下一首、暂停、播放。
- 连续重复播放/暂停命令：保持指定状态。
- 封面：读取 Windows 返回的图片字节并比较 SHA-256，确认换歌时封面更新；无封面歌曲清除旧图。
- 后台：最小化到托盘后切歌、暂停仍然有效，浏览器频谱副本不保留音频源。
- 缓存队列：曲库中不存在的缓存歌曲仍可连续切换。
- 原生播放结束：无缝续播与单曲循环后的媒体卡片跟随当前歌曲。
- 已打包后端：从测试 WAV 提取内嵌封面，验证原图 3000×2000、列表图 320×213、播放器图 768×512，确保图片处理原生依赖随包可用。

测试输出保存在 `.cache/desktop-smoke-*/results.json`，启动和播放器日志位于同一测试目录。NSIS 安装程序构建后校验 SHA-256；未覆盖用户当前安装。

## 封面内存对照

使用相同 Electron 版本、独立新进程、20 张不同的 3000×3000 PNG 封面，在相同的 128px 网格中完成解码和截图渲染，等待 1 秒后通过 `app.getAppMetrics()` 读取数据。对照组使用原图，优化组使用 320px WebP 缩略图。

可运行 `node scripts/benchmark-covers.cjs` 重现此对照，原始结果保存在 `.cache/cover-memory/*.json`。

| 指标 | 原图 | 缩略图 |
| --- | ---: | ---: |
| 渲染进程工作集 | 401.62 MiB | 111.82 MiB |
| Electron 进程私有内存总和 | 198.49 MiB | 178.52 MiB |

工作集和私有内存属于不同口径，不应相加。此测试衡量大封面列表场景，不能解释为所有页面或整款播放器固定降低相同比例。新图片处理模块按需加载，使用磁盘缓存并关闭 libvips 解码缓存；云端播放无需预先载入该模块。

此次保留界面动画、频谱、原图复制和音频质量设置，没有通过周期性强制 GC 或裁剪工作集来制造较低的内存读数。不同声卡、驱动和长期使用场景仍可能存在环境相关问题，本记录不代表对所有设备作无缺陷保证。
