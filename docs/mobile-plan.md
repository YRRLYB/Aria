# Aria 移动端企划(0.1.4 → 0.4)

> 2026-09 制定。目标:从「局域网伴侣」演进为「双端独立、按需同步」的二人成行架构,
> 同时完成刘海适配、桌面同款 Logo、无损播放显性化三个体验补课。

## 一、现状盘点(0.1.3)

已稳定:局域网连接(令牌配对)、网易云全功能串流(喜欢/每日/漫游/歌单/歌词/搜索)、
原生前台服务播放(后台 + 锁屏媒体卡片)、沉浸式播放页(封面主色渐变)、断线重连。

已知短板:
1. 手机强依赖电脑在线——桌面一关,手机全废。
2. 无跨网同步:播放历史/喜欢/进度只存在各自设备上。
3. 刘海/状态栏遮挡:内容与系统时钟、电量重叠(WebView 边距未处理)。
4. App 图标还是 Capacitor 默认图标。
5. 无损链路已在用(服务端默认 lossless 档,ExoPlayer 原生解码 FLAC),
   但界面没有把真实音质(码率/采样率)显性化,HiFi 档位与实际流未完全联动。

## 二、核心方案与可行性

### 方案 A:手机独立化(二人成行的主体)

| 路线 | 做法 | 可行性 | 代价/风险 |
|---|---|---|---|
| **A1. Kotlin 原生接入网易云(推荐)** | 用 Kotlin 重写网易云客户端:请求签名(weapi AES+RSA,算法公开且有 Go/Rust/Dart 参考实现)+ 9 个核心接口(QR 登录、账号、喜欢列表、每日推荐、私人漫游、歌单、搜索、歌词、song_url_v1 取流地址)+ Cookie 存储 | **~85%** | 1~2 周工作量;接口变动需跟随(与桌面 Node 版同等风险);需模拟客户端头降低风控 |
| A2. 嵌入 Node 运行时跑 NeteaseCloudMusicApi | nodejs-mobile libnode + 自维护 Capacitor 插件 | ~60% | capacitor-nodejs 已停更(2022);APK +40MB、内存 +100MB、工具链需自维护。**不推荐** |
| A3. 云中继代理全部 API | 手机所有网易云请求经云端转发 | 0%(非独立) | 桌面/云不在线即失效;仅作过渡 |

**A1 完成后的形态**:手机在地铁/流量下可独立扫码登录网易云,听每日推荐、私人漫游、
喜欢的、歌单、搜索、看歌词——桌面完全不需要开机。桌面唯一独占价值 = 本地曲库串流。

### 方案 B:双端同步(非局域网可用)

| 路线 | 做法 | 可行性 | 代价/风险 |
|---|---|---|---|
| **B1. Cloudflare Workers + D1(推荐)** | 免费额度(10 万请求/天)做轻量同步中继:两台设备用配对码入同一个命名空间,增量同步播放历史/喜欢/设置;载荷极小(每人每年 <1MB),可选端到端加密 | **~90%** | 需要你注册一个免费 Cloudflare 账号;我们提供一键部署脚本 |
| B2. Tailscale/FRP 把桌面暴露公网 | 零代码(现有局域网模式直接复用),外网也能连桌面 | ~95%(纯运维) | 依赖桌面开机;不算独立,但**远程串流桌面曲库**是独有价值,保留为增值功能 |
| B3. P2P 打洞直连 | WebRTC/libp2p | ~60% | NAT 类型依赖强、下发打洞服务仍需公网组件,首发不建议 |

**同步协议(轻量设计)**:
- 数据分三类:播放历史(append-only,合并去重)、喜欢集合(集合并)、
  播放进度/设置(按条目 last-write-wins,带时间戳)。
- 传输:局域网内直连桌面同步(已有链路);跨网走 B1 中继;两端都离线时本地排队,恢复后续传。
- 同步完全增量,每次 <10KB。

### 方案 C:局域网模式保留(增值)

保留现有伴侣能力,定位为「桌面大曲库遥控器 + 串流音箱」:
手机控制电脑播放、把电脑无损曲库推到手机/其他设备听。与独立模式共存,
数据源层面做统一抽象(本地直连源 / 桌面源),UI 上显示曲目来源。

## 三、目标架构(0.4 完成后)

```
手机 App
├─ 数据层:Room/SQLite 本地仓(历史/喜欢/进度/设置)
├─ 源1:网易云直连(Kotlin 原生,A1)
├─ 源2:Aria 桌面(局域网串流,现有能力)
├─ 同步引擎:LAN 直连优先 / Cloudflare 中继兜底 / 离线排队
└─ 播放:ExoPlayer 前台服务(现有)
电脑 Aria
├─ 现有全部能力不变
└─ 同步节点 + 串流源
```

## 五、已定决策(2026-09-12)

1. **独立化走 A1(Kotlin 原生)**——要求 APK 流畅、占用小;并且**对后续维护的 AI agent 友好**:
   - 网易云接入做成独立模块 `netease-client`,一个接口一个文件,入口 `NeteaseClient.kt` 单类;
   - 模块自带 `NETEASE_API.md`(每个接口:路径/参数/签名要点/返回结构)与 golden 单测
     (固定输入 → 固定签名字节,任何人/任何 agent 改完跑测试即知有没有改坏);
   - 加密实现只写一份(`Crypto.kt`),签名逻辑不超过 200 行,注释引用公开参考实现。
2. **同步走 B1(Cloudflare Workers + D1)**——注册免费账号,提供一键部署脚本;
   同步协议与中继解耦,未来可换通道。
3. Tailscale 远程串流作为零代码增值,出配置指南即可。
4. 局域网伴侣模式永久保留(桌面曲库串流/遥控)。

## 六、风险

| 风险 | 概率 | 对策 |
|---|---|---|
| 网易云接口/加密变更 | 中 | 桌面 Node 版与手机 Kotlin 版共用「接口变更观察」;签名层做单测 golden 样本 |
| 网易云风控(高频请求) | 低中 | 沿用桌面已有的缓存/节流策略;移动端默认保守刷新间隔 |
| Cloudflare 免费额度/政策变化 | 低 | 同步协议与中继解耦,可换任何静态托管 |
| M1 边距方案与个别 ROM 冲突 | 低 | force 模式 + CSS safe-area 双保险,支持配置回退 |
