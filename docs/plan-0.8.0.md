# Aria 0.8.0 更新方案介绍 —— 跨越的一代

> 主题：**YouTube Music 第四音源（仅它可配代理） · B站歌单 · 歌单交互重构 · 年度声迹重做**
> 基线：0.7.4（56 个测试文件 / 339 项单测）
> 完成态：60 个测试文件 / **378 项单测全绿**；`tsc -b`、`build:web`、`build:server`、后端冒烟全部通过

## 一、为什么 0.8.0 是跨越的一代

0.7.x 把「国内音乐生态」聚合到了一张桌面：本地无损、网易云、QQ 音乐、B站。0.8.0 把墙外的 YouTube Music 也搬了进来——并且解决了一个所有聚合播放器都绕不开的矛盾：

**YouTube 需要代理才能访问，而网易云 / QQ / B站在走代理时反而会变慢、触发风控。**

0.8.0 的答案是**按源代理**：设置里为 YouTube 单独填写一个 HTTP 代理端口（如 Clash 的 `7890`），只有 YouTube 的搜索、播放地址解析、封面与音频流走这个代理；其它三个在线源**永远直连**，国内使用体验分毫不动。

```
┌────────────┐   直连（不受代理影响）
│ 网易云     │──────────────► music.126.net
│ QQ 音乐    │──────────────► y.qq.com
│ B站        │──────────────► api.bilibili.com
├────────────┤
│ YouTube    │──► 用户代理（127.0.0.1:7890）──► music.youtube.com
│  (可选)    │                                      googlevideo.com
└────────────┘                              i.ytimg.com
```

## 二、YouTube Music 音源（新音源）

### 2.1 能力范围

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 歌曲搜索 | ✅ | music.youtube.com 官方内部 API（innertube WEB_REMIX），结果并入统一搜索池 |
| 音频播放 | ✅ | `player` 接口多客户端上下文回退链（IOS → ANDROID → WEB_EMBEDDED_PLAYER），取纯音频自适应格式 |
| 音质选择 | ✅ | AAC 128k（itag 140）→ standard；Opus ~70k（250）→ higher；Opus ~160k（251）→ exhigh，请求更高档位时自动降级 |
| 封面 | ✅ | `i.ytimg.com/vi/<id>/hqdefault.jpg`，经服务器缓存代理（同样走 YouTube 代理） |
| 账号登录 | ✅ | **窗口登录**（主路径）：应用内打开真实 Chromium 窗口，像平时一样登录 Google 账号后自动提取会话；窗口会话绑定用户配置的 YouTube 代理。Cookie 粘贴仅作备用。登录态经 player 响应的 `loggedin` 标记探测，探测不可达时按「已保存未确认」处理 |
| 歌单（统一歌单页） | ✅ | 登录后歌单页出现「YouTube」标签：账号音乐播放列表（只读）+ 固定置顶的「喜欢的音乐」；详情自动跟随 continuation 翻页 |
| 歌词 | ❌ | 视频字幕不适合当歌词展示，暂不启用 |
| 喜欢（单独入口） | ❌ | 喜欢的音乐作为歌单页的一张固定歌单展示，不单独开「我喜欢」入口 |

- 曲目身份采用 0.6.0 就预留的 `youtube:<videoId>` TrackKey，队列/历史/本地歌单零迁移即可混入。
- 搜索无总页数概念：用 innertube `continuation` 令牌翻页（服务端短 TTL 缓存令牌），「加载更多」照常工作。
- `playabilityStatus` 被风控拦截（LOGIN_REQUIRED）时给出可操作文案：提示稍后再试或更换代理出口 IP。

### 2.2 代理架构（核心设计）

**服务端**（`server/sources/youtube/client.ts`）

- 设置持久化在 `store.json` 的 `youtubeProxy` 字段，支持三种写法：`7890`、`127.0.0.1:7890`、`http://…:7890`（统一规范化为完整 URL；目前仅支持 HTTP 代理，socks 会被明确拒绝）。
- 基于 `undici` 的 `ProxyAgent` 实现：所有 YouTube 请求（搜索、播放解析）通过 `undici.fetch(url, { dispatcher })` 走代理；代理设置**每次请求现查**（2 秒缓存），改完设置立即生效，无需重启。
- **音频流与封面同路由**：googlevideo 的流地址绑定解析时的出口 IP，所以取流必须走同一个代理——`SourceStreamMeta` 新增进程内 `fetcher` 字段（绝不下发渲染端），`streamProxy` 优先用它取上游；封面缓存 `RemoteCoverCache` 同样注入代理感知的 fetcher。
- 错误映射：代理端口未运行 → 6ms 内返回「无法通过代理访问 YouTube，请确认代理端口正在运行」；未配置代理且直连失败 → 「无法连接 YouTube，请检查网络或在设置里配置代理端口」。
- **网易云 / QQ / B站的请求代码一行未动**——它们不读代理设置、不经过 dispatcher，这是"不影响国内使用效果"的结构保证，不是约定。

**前端**

- 设置 → 播放源新增 **YouTube Music 卡片**：启用/停用开关 + 代理端口输入框 + 保存/清除 + **测试连接**（真实发一次搜索验证链路），并明示「代理仅作用于 YouTube」；**窗口登录**（与 QQ 窗口扫码同一交互范式）为主登录路径，登录窗口会话同样走 YouTube 代理，Cookie 粘贴仅作备用。
- 右上角**头像账号面板**加入 YouTube 卡片，与网易云/QQ/B站并排显示登录态。
- 首页锁定为固定画布（绝不允许纵向拖动）；年度声迹月份预览用固定小方格（略大于 0.7.4），悬浮方块可见当天日期与播放次数。
- 歌单页统一五标签：网易云 / QQ / B站 / **YouTube** / Aria歌单——登录后「YouTube」标签展示账号音乐播放列表（喜欢的音乐固定置顶、全部只读），与 B站收藏夹同一套交互范式。
- 搜索页来源芯片新增 YouTube（官方红底播放键矢量图标 + 红色徽章），单源筛选、单源队列、加载更多全部对齐。
- 新手教程第 2 步加入 YouTube 提示：无法直连时去设置配代理即可，其它源不受影响。

### 2.3 验证记录（代理与账号链路）

本地后端冒烟（`ARIA_API_PORT=3663`）：

1. `GET /api/sources` 正确上报 youtube manifest（`playback: true`、`qualitySelection: true`、`account: true`、`playlistsRead: true`）。
2. `PUT /api/settings/youtube-proxy {"proxy":"7890"}` → 规范化为 `http://127.0.0.1:7890`；`"abc"` → 400 `YOUTUBE_PROXY_INVALID`；空串清除。
3. **死代理验证**：设置 `127.0.0.1:99` 后搜索在 **6ms** 内失败并返回代理专属文案——证明请求确实经过了 ProxyAgent（本机直连 YouTube 会挂满 10 秒超时）。
4. 清除代理后网易云搜索请求行为不变（直连链路未被触碰）。
5. **账号链路**：未登录 `/account` → `connected: false`；粘贴含 SID 的 Cookie → 200 保存（探测不可达时按「已保存未确认」返回 `connected: true`）；缺 SID 的 Cookie → 404 拒绝并附 DevTools 导出指引；登录后读歌单在直连不可达时返回 502 + 「请配置代理端口」文案；`DELETE /cookie` 退出后账号态复位，`/api/settings` 如实上报 `hasYoutubeCookie`。

## 三、B站歌单与歌单交互重构（歌单页统一五标签）

```
歌单页
├─ 网易云     （原样：新建/我创建/我收藏/完整编辑）
├─ QQ 音乐    （原样：只读同步）
├─ B站        （新增）
│   ├─ 我的收藏夹：登录后自动同步账号全部收藏夹（含私密、只读）；
│   │           点开即播；「Aria」红心收藏夹不重复列出
│   └─ 引入的B站歌单：粘贴公开收藏夹/合集/b23.tv 短链生成镜像，
│                   卡片上可刷新/删除，点开跳 Aria 歌单详情
├─ YouTube    （新增）
│   └─ 登录后同步账号音乐播放列表（Cookie 绑定、只读），
│       「喜欢的音乐」固定置顶，详情自动翻页
└─ Aria歌单   （本地混合歌单；移除了冗余的"网易云/本地"迷你切换）
```

- 服务端新增通用路由 `GET /api/sources/:id/playlists` 与 `/:playlistId/tracks`（B站 playlistId 形如 `folder:<id>` / `season:<mid>:<id>`）；收藏夹登录态 5 页并发批量读取，上限 500 条；B站 manifest 声明 `playlistsRead`。
- **镜像刷新不再吞歌**：`mergeReferenceSync` 只替换 B站来源部分，手动混入的本地/网易云/QQ 歌曲保留在列表末尾。
- B站歌曲行内「加入歌单」入口恢复（0.7.4 对 B站源直接隐藏）。
- 视图后退栈完整保留 B站标签与收藏夹详情（`ViewHistorySnapshot.bilibiliPlaylist`）。

## 四、年度声迹重做（两个 bug + 一个数据模型根因）

**问题定位**：放大后显示的是「过去 53 周」滚动窗口（跨两个自然年却标着"全年"）；首页预览是"近 18 周"；而数据源（80 条去重播放历史、重复播放刷新时间戳）先天撑不起全年图。

**修复**：

- 年度视图严格 **1月1日–12月31日**（首尾周对齐补位空格），新增 **‹ 年份切换 ›**；
- 首页不点开时只显示**当前一个月**（"11月 · 放大 / 本月 N 次播放"）；
- 新增**每日聆听日志** `aria-daily-activity`（按天聚合，一年约 365 个键，保留 3 年），首次升级用旧历史自动回填；日期步进改用日历日（DST 安全）。

## 五、顺手优化与修复

1. B站收藏夹导入上限 200 → 500 条，登录态读取改为 5 页并发批量。
2. `SourceToggle` 泛型化（值域由 options 决定），四来源滑块定位无需改动。
3. B站收藏夹列表登录缓存（`favPlaylistsCache`）纳入统一失效治理。
4. 搜索页来源芯片/队列/错误横幅对 YouTube 全套补齐。
5. 前端 `ProviderPlaylist.source`、`Track.source` 等联合类型补全 `"youtube"`。

## 六、后续优化方向（0.8.x 候选）

1. **YouTube 歌词**：优先接 Musixmatch/网易云匹配（歌名+歌手），比 CC 字幕可靠。
2. **YouTube 账号增强**：昵称/头像解析（账号页 HTML 或 sw.js_data）、「我喜欢」单独入口、搜索限定「我点的赞」结果。
3. **代理高级设置**：支持 socks5（需引入 socks dispatcher）、代理连通性周期探测与状态提示。
4. **B站收藏夹写操作**（多夹子目标）、**我的合集自动同步**（`season/series_list`）。
5. 镜像歌单自动后台刷新（按 syncedAt 定期 re-resolve）。
6. 「听歌洞察」统计页接入每日日志，做"本年 vs 去年"对比。
7. QQ 歌单写操作（维持既定路线图）。
8. Aria-Mobile 展示年度声迹与 YouTube 源（局域网同步每日日志）。

## 七、兼容性与迁移

- 升级零迁移：每日日志为空时自动播种；`youtube:` TrackKey 0.6.0 起即预留；本地歌单存储结构不变。
- 未配置代理时 YouTube 源依旧注册（可搜索不可达时会给出明确文案），不影响其它源；也可在设置里整体停用该源。
- 旧引用歌单（0.7.1+ 的 `remoteRef`）原样兼容，刷新走新的合并语义。
- 新依赖：`undici@^7.28.0`（服务端代理 HTTP 栈，纯 JS，esbuild 直接打包进 `dist-server`）。
